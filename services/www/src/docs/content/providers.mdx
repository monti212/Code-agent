U Code offers three providers. Uhuru AI is built in and is the default. OpenAI and Anthropic are available when you
bring your own API key for them.

| Provider | Provider ID | Credential |
| --- | --- | --- |
| Uhuru AI | `uhuru` | Uhuru API key, `UHURU_API_KEY` |
| OpenAI | `openai` | Your OpenAI API key, `OPENAI_API_KEY` |
| Anthropic | `anthropic` | Your Anthropic API key, `ANTHROPIC_API_KEY` |

## Setup

Run `/connect`, choose a provider, and enter its credentials. Then run `/models` to select one of its models.

```text
/connect
/models
```

From a shell, `ucode auth login` does the same. See [Provider accounts](/cli/providers).

## Uhuru AI

Uhuru AI is U Code's default provider. Create an API key at [uhuruai.co](https://uhuruai.co) under
**Settings → API Keys**. Keys start with `uhuru_sk_`.

```text
/connect
# Select Uhuru AI, then paste your API key.
/models
```

You can also provide the key through the environment:

```bash
export UHURU_API_KEY=uhuru_sk_...
ucode
```

| Setting | Value |
| --- | --- |
| Provider ID | `uhuru` |
| Models | `uhuru-4.0` (U4.0, the default) and `uhuru-5.0` (U5.0, for the hardest work) |
| Base URL | `https://ucloud.orionx.xyz/functions/v1/ucode-api/v1` |
| Wire format | Standard chat-completions |

Select a model with its reference, for example `uhuru/uhuru-4.0`, or make it the default in config:

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "uhuru/uhuru-4.0",
}
```

<Callout>
  U4.0 and U5.0 can use U Code's tools, such as file edits and shell commands, and accept images. Access is opening
  in stages: if a request is refused with "U Code is not enabled for your account yet", your account is not included
  yet.
</Callout>

## Bring your own key

OpenAI and Anthropic models are listed under their own names. They run on your account with that provider and are
billed by that provider. They also need your Uhuru AI account connected: until it is, they stay unavailable in U Code.

```text
/connect
# Select OpenAI or Anthropic, then paste your API key.
/models
```

Or set the key in the environment before starting U Code:

```bash
export OPENAI_API_KEY=sk-...
export ANTHROPIC_API_KEY=sk-ant-...
ucode
```

Model references take the form `openai/<model>` and `anthropic/<model>`, for example `openai/gpt-5.2` or
`anthropic/claude-sonnet-4-6`. OpenAI also offers sign-in with a ChatGPT Pro or Plus account from the same
`/connect` dialog.

## Endpoint

Override `settings.baseURL` to send a provider through your own proxy. Its models and connection still apply.

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "anthropic": {
      "settings": {
        "baseURL": "https://llm-proxy.example.com/anthropic",
      },
    },
  },
}
```

`settings` is package-specific. A field only has an effect when the selected package supports it.

## Requests

Use `headers` for additional HTTP headers and `body` for JSON fields that should be merged into every request body.

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "headers": {
        "X-Gateway-Tenant": "engineering",
      },
      "body": {
        "metadata": {
          "application": "ucode",
        },
      },
    },
  },
}
```

Both fields can also be set on a model or variant when only part of a provider's traffic needs the override.

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "models": {
        "gpt-5.2": {
          "headers": { "X-Model-Tier": "coding" },
          "variants": [
            {
              "id": "batch",
              "body": { "service_tier": "flex" },
            },
          ],
        },
      },
    },
  },
}
```

## Models

Add or override models in a provider's `models` map. The map key is the model ID used by U Code; `modelID` changes the
ID sent to the provider.

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "model": "openai/coding",
  "providers": {
    "openai": {
      "models": {
        "coding": {
          "modelID": "gpt-5.2",
          "name": "GPT-5.2 Coding",
        },
      },
    },
  },
}
```

| Field | Purpose |
| --- | --- |
| `modelID` | Model or deployment ID sent to the provider. |
| `name` | Display name. |
| `family` | Model family used for grouping related models. |
| `package` | Runtime override for this model. |
| `settings` | Package-specific JSON settings. |
| `headers` | Additional string-valued request headers. |
| `body` | Additional JSON request body fields. |
| `capabilities` | Tool support plus accepted input and output media types. |
| `compatibility` | Request and response compatibility overrides. |
| `variants` | Named variants with their own `settings`, `headers`, and `body`. |
| `cost` | Input, output, and optional cache pricing per million tokens. |
| `limit` | Context, input, and output token limits. |
| `disabled` | Removes the model from selection when `true`. |
| `transport` | Model-level session transport; overrides the provider value. |
| `compaction` | Model-level [compaction](/compaction) policy; overrides the provider policy. |

See [Models](/models) for selection, defaults, capabilities, limits, costs, and variants.

## Errors

Provider and model errors usually identify the failed stage. Check the server process environment and the exact model
ID before changing settings.

| Error or symptom | Check |
| --- | --- |
| `No model is available for session ...` | No provider is connected yet. Connect Uhuru AI, or your own OpenAI or Anthropic key, then choose a model in `/models`. |
| `Model unavailable: provider/model` | The provider is not connected, or the model ID is absent or disabled. For custom aliases, check the `models` map key rather than `modelID`. |
| `Cannot initialize provider/model: NAME is required to resolve the provider endpoint` | A `${NAME}` placeholder remains in `baseURL`. Set that variable on the U Code server or replace the template with a complete endpoint. |

## WebSockets

Supported OpenAI models can keep one WebSocket connection open per session. Consecutive steps
reuse the unchanged request prefix and only send content added since the previous response, reducing uploads in long
sessions.

```jsonc title="ucode.jsonc"
{
  "$schema": "https://opencode.ai/config.json",
  "providers": {
    "openai": {
      "transport": "http",
      "models": {
        "gpt-5.5": { "transport": "websocket" },
      },
    },
  },
}
```

WebSocket behavior follows these rules:

- Built-in providers opt supported models in according to their own policy.
- `transport: "websocket"` enables a provider or model; `"http"` disables it.
- A model value overrides its provider value.
- `"websocket"` on a route without a WebSocket channel logs a warning and falls back to HTTP.
- OpenAI provider compaction uses the same connection.
- A closed socket reconnects on the next step. If the connection cannot open, the session continues over HTTP.
- Provider plugins with `http.request` or `http.response` hooks stay on HTTP so each request remains observable.
